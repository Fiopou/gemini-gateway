# Gemini Gateway

Локальный OpenAI-совместимый шлюз к Gemini API (free tier) с пулом ключей и каскадом моделей. Основной код — `gateway.py`; внешние Python-пакеты не требуются. Рекомендуется Python 3.9+.

## Быстрый старт

```bash
git clone https://github.com/Fiopou/gemini-gateway.git
cd gemini-gateway
python gateway.py serve --port 8788
```

При первом запуске шлюз попросит API-ключи (по одному, пустой ввод — закончить) и сохранит их в `.env`:

```text
Ключи Gemini не найдены — настроим один раз.
Взять: https://aistudio.google.com/apikey -> Create API key (новый проект = новая квота).
Ключ (AIza...): _
```

Ключ бесплатный, лимиты висят на **проекте**: чем больше проектов (ключей), тем больше дневная квота.

### Прокси (важно)

Google отдаёт `400 User location is not supported` с некоторых регионов. Без рабочего прокси шлюз не сможет ходить в API. Включи локальный HTTP-прокси (v2rayNG / NekoBox, обычно `http://127.0.0.1:10809`) и пропиши его в `.env`:

```text
GEMINI_PROXY=http://127.0.0.1:10809
```

Пустое значение `GEMINI_PROXY=` — запросы напрямую (если твой регион поддерживается).

## Запуск

Из каталога `gemini-gateway`:

```bash
python gateway.py serve
```

По умолчанию шлюз слушает только `127.0.0.1:8788`, а стартовый тестовый запрос к Gemini отключён. Для OpenAI-совместимых клиентов укажи базовый URL:

```text
http://127.0.0.1:8788/v1
```

Модель для клиента (Janitor и т.п.): `gemini` (каскад) или конкретная, например `gemini-3.8-flash`.

Список моделей можно вывести без обращения к API и без наличия ключей:

```bash
python gateway.py models
```

Обычный запрос:

```bash
python gateway.py chat "Привет" -m gemini
```

Чтобы явно разрешить запусковый probe (он расходует квоту), перед запуском задай `GATEWAY_PROBE=1`. Чтобы привязать сервер к другому адресу, используй `python gateway.py serve --host 0.0.0.0`; это намеренное изменение сетевой доступности, а не рекомендуемый локальный режим.

## Ключи и квоты

`GEMINI_KEYS` в `.env` поддерживает список API-ключей через запятую. Пул предполагает **один ключ на отдельный проект**. Квоты Gemini API считаются на проект, не на отдельный ключ; поэтому несколько ключей одного проекта не создают независимые квоты. Смотри [официальное описание лимитов Google](https://ai.google.dev/gemini-api/docs/rate-limits).

Каскад по умолчанию: `gemini-3.8-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` → `gemini-3-flash-preview`. `gemini-3.7-flash` оставлен для ручного выбора и совместимости, но не используется как отдельная ступень каскада: Google автоматически перенаправляет этот ID на `gemini-3.8-flash` ([документация модели](https://ai.google.dev/gemini-api/docs/models/gemini-3.7-flash)).

Когда в теле ответа об ошибке явно указано ограничение на день, шлюз блокирует пару «модель + ключ» до следующей полуночи по тихоокеанскому времени. Для иных 429 учитывается `Retry-After`; если заголовка нет — применяется минутный cooldown. Счётчики локальные и сбрасываются при перезапуске процесса.

## Переменные окружения

Все переменные необязательны, если не указано иное:

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `GEMINI_KEYS` | Ключи разных проектов через запятую | Берётся из `.env` |
| `GEMINI_PROXY` | HTTP(S)-прокси для upstream-запросов | `http://127.0.0.1:10809` |
| `GATEWAY_HOST` | Адрес привязки; можно переопределить через `--host` | `127.0.0.1` |
| `GATEWAY_PORT` | Порт; можно переопределить через `--port` | `8788` |
| `GATEWAY_TOKEN` | Токен локального шлюза; проверяется, если задан | Пусто |
| `GATEWAY_MAX_CONTEXT` | Оценочный лимит контекста; `0` отключает ограничение | `0` |
| `GATEWAY_MAX_REQUEST_BYTES` | Максимальный размер JSON-тела | `10485760` (10 MiB) |
| `GATEWAY_COMPACT_CHUNK` | Размер фрагмента старой истории для резюмирования | `25000` символов |
| `GATEWAY_COMPACT_MAX_CHUNKS` | Максимум фрагментов за одну компактизацию | `8` |
| `GATEWAY_COMPACT_KEEP_MESSAGES` | Сколько последних сообщений сохранять без резюме | `4` |
| `GATEWAY_COMPACT_MODEL` | Модель для резюмирования старой истории | `gemini-3.5-flash-lite` |
| `GATEWAY_PROBE` | Выполнить тестовый upstream-запрос при старте, `1`/`0` | `0` |
| `GATEWAY_CORS_ORIGINS` | Явный список origin через запятую; `*` отключает фильтрацию origin | Loopback-origin (`localhost`, `127.0.0.1`, `::1`) |

Оценка токенов — консервативная локальная эвристика, а не официальный токенизатор Google. Если после резюмирования контекст всё ещё превышает `GATEWAY_MAX_CONTEXT`, шлюз вернёт `413`, а не отправит запрос, превышающий заданный лимит. Слишком большую историю (более `GATEWAY_COMPACT_MAX_CHUNKS` фрагментов) он не обрезает молча.

## Проверки

Из каталога проекта:

```bash
python -m unittest discover -s tests -v
python -m py_compile gateway.py tests/test_gateway.py
```

Тесты запускают HTTP-сервер на loopback и подменяют upstream-функции тестовыми ответами. Они **не отправляют запросы в Google API и не расходуют квоту**. Первый реальный запрос следует отдельно проверить в своей сети с настроенным прокси и действующими ключами.
